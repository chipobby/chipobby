# Kit del instructor — Puesta en marcha y operación

**Fase:** Fase 6 — Recursos
**Público:** facilitadores que impartirán el curso.
**Uso:** leer antes de la sesión 1; revisar el punto 3 antes de cada sesión.

---

## 1. Antes de impartir (una sola vez, ~45 min)

- [ ] Leer `DOCUMENTACION/DISENO_PEDAGOGICO.md` (§1 progresión, §4 requisitos, §8 gamificación).
- [ ] Ejecutar la **lista de verificación técnica** de `DOCUMENTACION/VERIFICACION_TECNICA.md` §7 en Roblox Studio (15 min).
- [ ] Preparar las **tarjetas de código** de `RECURSOS/TARJETAS_CODIGO.md` (imprimir/recortar).
- [ ] Preparar hojas de **autoevaluación** (`EVALUACION/AUTOEVALUACION_INFANTIL.md`) y **listas de chequeo** (`EVALUACION/LISTAS_CHEQUEO_MODULOS.md`).
- [ ] Verificar **seguridad**: cuenta educativa/roblox configurada, sin compras, sin chat pública (`RECURSOS/REQUISITOS_TECNICOS_Y_SEGURIDAD.md`).
- [ ] Imprimir la **guía del participante** para cada niño (`RECURSOS/GUIA_DEL_PARTICIPANTE.md`).
- [ ] Revisar `PROYECTO_INTEGRADOR/ESPECIFICACION.md` (9 requisitos P1–P9).

## 3. Antes de cada sesión (10 min)

1. Abrir la guía `MODULOS/SESION_xx.md` y leer **§7 materiales**, **§9 tiempos** y **§15 errores frecuentes**.
2. Revisar **§1 prerrequisitos**: si algo anterior quedó "En proceso", planear el apoyo.
3. Tener a mano la **tarjeta de código** (si es sesión de código) y las fichas.
4. Definir a quién observar hoy (muestreo: 3–4 participantes, ver `EVALUACION/GUIA_OBSERVACION.md` §6).
5. Recordar el **hito del proyecto** (columna "Requisito" de §1) para orientar el cierre.

## 4. Estructura fija de 90 minutos

| Min | Bloque | Notas |
|---:|---|---|
| 0–10 | Bienvenida | Recordatorio del hito + historia de Chip |
| 10–25 | Demostración | Clic por clic; el facilitador hace, el grupo observa |
| 25–45 | Práctica guiada | Acompañar; no tomar el mouse salvo petición explícita |
| 45–50 | **Pausa activa** | Obligatoria: movimiento + descanso visual |
| 50–70 | Reto individual | Con variantes fácil/difícil (§12) |
| 70–80 | Prueba | Verificación con criterio de éxito (§14) |
| 80–90 | Cierre | Reflexión (§18) + insignia si aplica + autoevaluación/lista si cierra módulo |

**Flexibilidad:** ver nota de tiempo en `PLAN_FORMATIVO.md` §5; si se corta, priorizar siempre demostración + prueba y dejar el reto para la siguiente.

| Insignia | Sesión de entrega | Evidencia mínima |
|---|---|---|
| 🎨 Creador de ideas | S01 | Tema + plano |
| 🔍 Explorador | S02 | Reconoce Explorer/Properties |

| 🏃 Probador | S08 | 1 mejora registrada |
| 💻 Programador novato | S10 | Mensaje en Output |
| ⭐ Cazador de estrellas | S13 | Coleccionable con criterio |
| 🛡 Guardián de reglas | S17 | Regla SI/ENTONCES funcionando |
| 🏆 Maestro del Obby | S20 | Presentación + checklist P1–P9 |

Registro: anotar entrega en la ficha individual (`EVALUACION/MATRIZ_EVIDENCIAS.md` → Registro individual). Material simbólico (parche, sticker o sello): **no usar Robux ni premios comprados**.

## 6. Manejo del grupo

- **Diferencias de ritmo:** el que termina primero usa la **variante de desafío** de §12 o la ampliación de §19; nunca "ocupa" la sesión del otro.
- **Participante atascado:** aplicar rúbrica C de `GUIA_OBSERVACION.md` (demostración → pasos → retirada gradual).
- **Errores rojos en Output:** normalizarlos ("materiales del creador"); usar la técnica de comparar con la plantilla.
- **Conflictos por temas/nombres:** el tema es individual; prohibido copiar el juego de otro (copiar líneas de código con la tarjeta sí está permitido y es parte del método).
- **Niño que no quiere presentar (S20):** aceptar señalar/dibujar; la evaluación es formativa.

## 7. Seguridad — recordatorio permanente

- Sin publicación del juego, sin chat pública, sin comprar Robux, sin datos personales en nombres ni mensajes.
- Revisar con el adulto cualquier asset externo **antes** de usarlo (por defecto: no se usan assets externos; todo se crea desde cero).
- Evidencias **sin rostros ni nombres completos**.
- Incidentes técnicos o de contenido: escalar al responsable del programa y registrar.

## 8. Después de cada sesión (5 min)

1. Llenar la **guía de observación** de los participantes observados.
2. Actualizar estados "En proceso/Requiere apoyo" → **próximo paso acordado**.
3. Si cierra módulo: aplicar **lista de chequeo** + **autoevaluación**.
4. Anotar incidencias técnicas (¿alguna API falló? ¿alguna ventana cambió?) para `VERIFICACION_TECNICA.md`.

## 9. Problemas comunes de operación

| Problema | Solución |
|---|---|
| Studio sin internet/cuenta | Trabajar en modo local si está disponible; si no, reprogramar la sesión (no se salta el prerrequisito) |
| Computador lento | Reducir el número de piezas; usar la variante "más fácil" |
| Output no aparece | View → Output (guía S10 §15) |
| El niño cerró Studio sin guardar | Repetir los últimos pasos; usarlo como lección "guardar siempre" |
| Faltan tarjetas impresas | Proyectar/copiar la plantilla a mano en papel grande |
